## ⛓️ Chain of Thought (CoT)

בקשה מהמודל לפרוס חשיבה שלב־אחר־שלב לפני התשובה הסופית – במיוחד כשיש לוגיקה, חישוב או כמה אפשרויות.

```text
אנא נתח את הבעיה באופן הדרגתי. הסבר כל שלב לפני התשובה הסופית.
אם יש כמה אפשרויות, פרט אותן וסמן מה הסביר ביותר.
רק בסוף הצג תשובה ברורה ומדויקת.
```

**מתי:** ניתוח, השוואה, תקלות מרובות שלבים.  
**מתי לא:** משימות פשוטות / עלות טוקנים רגישה – CoT "יקר".

---

## ⚡ ReAct Prompting (Reasoning + Action)

במקום תשובה רק מהידע הפנימי – לולאה: **חשיבה → בחירת פעולה → תצפית → חזרה**.

```text
קרא את השאלה וחשוב על הצעד המתאים.
בחר פעולה אחת בלבד:
  search()  - חיפוש ממקור חיצוני
  fetch()   - שליפה ממסד נתונים
  explain() - ניסוח תשובה על סמך המידע הקיים
ציין את הפעולה ואת הסיבה לבחירה.
```

| מושג | משמעות |
|------|--------|
| Thought | מה אני חושב שצריך |
| Action | איזה כלי / צעד |
| Observation | מה חזר מהעולם |
| Final | תשובה למשתמש |

> **חיבור לשיעור 1:** ReAct הוא *התנהגות*; Function Calling הוא *המימוש* של ה-Action.

---

## 🔗 Prompt Chaining

פירוק משימה מורכבת לכמה פרומפטים עוקבים – כל שלב מזין את הבא.

**דוגמה: יצירת מאמר**

1. מתווה (כותרת + 3–5 סעיפים) – בלי פסקאות  
2. פתיח על בסיס המתווה  
3. גוף – פסקה לכל סעיף  
4. סיכום על בסיס פתיח+גוף  

**יתרונות:** פיקוח, תיקון באמצע, פחות Context Rot בגלל שאילתה אחת ענקית.  
**חסרונות:** יותר קריאות API, צריך אורקסטרציה בקוד.

---

## 🌀 Self-Consistency

המודל הסתברותי → מריצים את אותו פרומפט מספר פעמים, בוחרים את התשובה החוזרת / הטובה ביותר.

```text
להלן מספר תשובות לאותה שאלה.
השווה לפי: דיוק לוגי · בהירות · התאמה לשאלה.
בחר גרסה אחת והסבר בקצרה מדוע.
```

מתאים למשימות שיש להן "תשובה נכונה" יחסית (סיווג, חישוב, החלטה בינארית).

---

## 🚀 Prompt Optimization

כותבים 2–3 גרסאות לאותה משימה, משווים תוצאות, בוחרים / ממזגים.

```text
1) כתוב כותרת שיווקית למאמר על ניהול זמן.
2) כותרת עד 8 מילים, טון חיובי, CTA.
3) Role: קופירייטר מנוסה… עורר סקרנות.
```

במערכות מתקדמות (DSPy וכו') – אופטימיזציה אוטומטית; בקורס מספיק תהליך ידני מודע.

## 🛠️ Lab: לולאת ReAct

שירות תמיכה על חיוב כפול. אותה הודעה פעמיים — **בלי לולאה** ואז **עם ReAct**.

המעבדה בכיתה היא חלון Gradio. הקוד: [`../demos/03-react-loop/`](../demos/03-react-loop/)

- **בלי לולאה** – תשובה ישר מהזיכרון. ממציאה החזר או מתנצלת. אין Observation.
- **עם ReAct** – Thought (זה CoT) → Action (`lookup_bill` / `lookup_policy` / `finish`) → הקוד מריץ → Observation → חזרה.
- **שרשרת מול Agent:** אם הקוד היה תמיד מריץ חיוב → מדיניות → מייל, זו שרשרת. כאן המודל בוחר את הסדר.

## 💡 טיפים ו-Gotchas

- ReAct בלי כלים אמיתיים = תיאטרון; בלי תצפית אמיתית אין ערך.
- Chaining טוב לפיקוח; Agent טוב כשהנתיב לא ידוע מראש (שיעור 8).
- אל תשלב CoT ארוך *בתוך* JSON מובנה – עדיף שדה `reasoning` נפרד או chain קודם.
- Optimization בלי מדד הצלחה = תחושת בטן; הגדירו 5–10 מקרי מבחן.

## ✅ לסיכום

- CoT משפר דיוק במשימות חשיבה.
- ReAct מחבר חשיבה לפעולה – בסיס לכל Agent.
- Chaining מפרק מורכבות; Self-Consistency ו-Optimization מעלים עקביות.
- בפרק הבא נעבור מ"מילים" ל**מספרים**: Embeddings.
