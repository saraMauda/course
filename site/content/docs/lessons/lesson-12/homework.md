## שלב 1 — `tools.py`

מחקי את התוכן, והדביקי **בדיוק** את זה:

```python
# המקורות של המומחיות בספרייה עירונית.
# שלושה מקורות עצמאיים. כל אחד "איטי" (LATENCY) כמו קריאת API אמיתית.

import json
import re
import time

LATENCY = 0.4  # שניות לכל מקור. סימולציית API

ACCOUNTS = {
    "205": {"customer": "205", "note": "קנס איחור של 12 ₪ על הספר «הנסיך הקטן», 12 ימי איחור."},
    "300": {"customer": "300", "note": "אין קנסות פתוחים."},
}

KNOWLEDGE = [
    {"id": "late-fee", "text": "איחור: קנס של 1 ₪ ליום איחור, עד תקרה של 30 ₪. ביטול קנס רק אחרי אימות מול הדלפק."},
    {"id": "loan", "text": "השאלה: 21 יום, עד 5 ספרים. הארכה אחת של 14 יום, באפליקציה."},
    {"id": "card", "text": "כרטיס מנוי: הנפקה בדלפק עם תעודה מזהה. כרטיס אבוד מוחלף תמורת 10 ₪."},
]

WEB_URL = "https://example.com/library-news"

_ACCOUNT_RE = re.compile(r"(?:לקוח|מנוי|חבר)\s*(?:מספר\s*)?(\d+)")


def extract_account_id(text: str) -> str | None:
    m = _ACCOUNT_RE.search(text or "")
    return m.group(1) if m else None


def _words(text: str, fuzzy: bool = False) -> set:
    words = {w for w in re.findall(r"\w+", text) if len(w) > 2}
    if fuzzy:  # סבב מורחב: מורידות אות יחס בתחילת מילה
        words |= {w[1:] for w in words if len(w) > 3 and w[0] in "הלבכמו"}
    return words


def kb_search(question: str, top_k: int, fuzzy: bool = False) -> list[dict]:
    """חיפוש מילות מפתח. בכל סבב top_k גדל, ומסבב שני גם התאמה גמישה."""
    time.sleep(LATENCY)
    words = _words(question, fuzzy)
    scored = [(len(words & _words(item["text"], fuzzy)), item) for item in KNOWLEDGE]
    scored.sort(key=lambda pair: pair[0], reverse=True)
    return [item for score, item in scored[:top_k] if score > 0]


def lookup_account(account_id: str) -> dict | None:
    time.sleep(LATENCY)
    return ACCOUNTS.get(account_id)


def web_search(question: str) -> str:
    """stub. «חדשות» = שירות החיפוש נופל. «עדכני» = תוצאה. אחרת: אין תוצאות."""
    time.sleep(LATENCY)
    if "חדשות" in question:
        raise TimeoutError("שירות החיפוש לא זמין")
    if "עדכני" in question:
        return f"[stub] {WEB_URL} — עדכון: שעות הפתיחה בחג משתנות."
    return ""


def dumps(data) -> str:
    return json.dumps(data, ensure_ascii=False)
```

שמות הפונקציות **נשארים**. רק התוכן משתנה.

## שלב 3 — `graph.py`: כלל העצירה שלך

מחקי את **הגוף** של הפונקציה `route_after_synth` (השאירי את החתימה) וכתבי אותה מחדש:

| דרישה | פירוט |
|-------|--------|
| יש מספיק מקורות | `len(state["sources"]) >= MIN_SOURCES` → מחזירה `END` |
| נגמרו הסבבים | `state["attempt"]` הגיע ל-`1 + MAX_LOOPS` → מחזירה `END` |
| אחרת | מחזירה `"plan"`. הגרף חוזר לתכנון וחיפוש מורחב |

רמז: `attempt` מציין כמה סבבים כבר רצו (`plan` מגדיל אותו). שימי לב לסדר: אסור שהלולאה תרוץ ללא סוף. אם כלל העצירה שלך שגוי, תקבלי שגיאת `recursion_limit`.

אל תשני שום דבר אחר ב-`graph.py`.

> עם מודל אמיתי הניסוחים והמספרים יכולים להשתנות. זה בסדר — תעדי מה קיבלת.

## שאלות להגשה

1. **טבלת קורא/כותב:** לכל node (`plan`, `kb`, `account`, `web`, `synthesize`), איזה שדות ב-State הוא **קורא** ואיזה הוא **כותב**. (הרמז: עברי על ה-`ResearchState` ועל הקוד של כל node.)
2. **Fan-in:** למה `sources` צריך Reducer (`merge_unique`), אבל `kb_notes` ו-`account_notes` לא? משפט או שניים.
3. **שלב 2 מול שלב 3:** מה היתרון ש-`plan` מחליט מי עובדת, מול שלוש מומחיות תמיד? (רמז: מבחינת עלות וקריאות למודל, בבדיקות 2 ו-3.)
4. **Global מול Local:** מה בדמו הוא "Global" (נשאר ב-State) ומה "Local" (נשאר בתוך ה-node)? למה `kb` לא כותב ל-State את כל הטקסט הגולמי מהחיפוש?
5. **תשובה חלקית:** בבדיקה 5, מה הייתה חלופה לגרף שממשיך עם תשובה חלקית? מה היתרון והחיסרון של כל אחת?
6. **לפרויקט 3:** (א) ציירי גרף Multi-Agent ל-NotebookLM (RAG + Web + Merge). (ב) הגדירי שדות State לכל node (מה קורא ומה כותב). (ג) כתבי כלל עצירה: מתי מפסיקים לחפש ומתי ממשיכים.
