## 🌟 הקדמה

במרכז היכולת לשלוט במערכות מבוססות LLM עומדת **הנדסת פרומפטים** – אומנות וניהול מדויק של הנחיות למודל, כדי להפיק תוצאות עקביות, מדויקות ורלוונטיות.

בחלק א' נתמקד ב**מבנה ובהנחיה**: איך להלביש את המודל בתפקיד, איך ללמד בדפוסים (Few-Shot), ואיך **לכפות פלט** שנוח לקוד – לפני שנצלול ללוגיקה ואורקסטרציה (חלק ב').

---

## 🆕 פרדיגמת פיתוח חדשה

### מאפייני הפיתוח הקלאסי
- קלט צפוי → תוצאה צפויה
- בדיקות יחידה פשוטות יחסית
- הפלט נחשב מהימן כי הוא יוצא מקוד שנבדק

### השינוי שמביאים ה-LLMs
- **תקשורת בשפה טבעית** – בלי לזכור פקודות
- **תהליך דינמי** – פירוש כוונה, לא רק כללים
- **פלט לא חד-ערכי** – אותה בקשה, כמה תשובות "נכונות"

---

## 📌 עקרונות בהנדסת פרומפטים

התהליך **איטרטיבי**. עמודי התווך:

| עיקרון | מה עושים |
|--------|----------|
| **Context** | רקע מלא: משימה, קהל, נתונים |
| **Instructions** | ניסוח ישיר, בלי הנחות סמויות |
| **Examples (Few-Shot)** | להראות איך נראה פלט רצוי |
| **Structured Output** | JSON / Markdown מוגדר מראש |

---

## 🧑‍💻 Role Prompting

הצבת המודל בתפקיד ברור מגדילה עקביות וממקדת את המענה. ההגדרה מכניסה אותו ל"חליפה" – ככל שהתפקיד מדויק יותר, איכות התשובות עולה.

```text
אתה מפתח בכיר ב-React. כתוב קומפוננטה המציגה כותרת.
אתה מתרגם טכני. תרגם את הטקסט ושמור על מונחים באנגלית.
```

---

## 🧾 Instruction Templates

תבנית קבועה עם משתנים דינמיים – סטנדרטיזציה וצפיות:

```text
סכם את הטקסט הבא ב־{מספר_מילים} מילים, בשפה {שפה}, בטון {טון}:
---
{תוכן}
---
```

---

## 🧱 Hard-Coding Context

מידע קבוע שהמודל לא "יודע לבד" – סטטוס לקוח, אזור, שפה:

```text
אתה פועל כעוזר וירטואלי של מערכת שירות לקוחות.
תמיד תתייחס לנתונים הבאים:
- סטטוס לקוח: פעיל
- אזור גאוגרפי: ישראל
- שפה מועדפת: עברית
```

---

## 🧠 Zero-Shot · One-Shot · Few-Shot

מודלים לומדים דפוסים, לא "כללים פורמליים". Few-Shot מלמד **על המקום**:

```text
סווג את הכוונה במשפט הנתון.
דוגמאות:
"מה השעה?" -> שאלה כללית
"תרגם את הטקסט הזה" -> בקשת תרגום
"צור לי קוד" -> בקשת קוד

המשפט: "איך מגדירים טבלה ב-html?"
```

| שיטה | מתי |
|------|-----|
| Zero-Shot | משימה פשוטה, המודל "מכיר" את התחום |
| One-Shot | דוגמה אחת מספיקה לפורמט |
| Few-Shot | סיווג, טון, מבנה עקבי |

---

## 📐 Output Structuring

כפיית מבנה – קריטי לאינטגרציה עם קוד:

```text
ענה ב-JSON בלבד עם השדות:
{
  "compliance": "yes|no",
  "category": "...",
  "riskLevel": "green|yellow|red"
}
```

ב-Python: **Pydantic** / **JSON Schema** ל-validation של הפלט (לא רק של הקלט!).

---

## 🧱 Guardrails Prompting

הגבלת נושא, סגנון ותוכן אסור:

```text
ענה רק על שאלות הקשורות לשירות הסלולר שלנו.
אם השאלה מחוץ לתחום – ציין שאין לך מידע והפנה לנציג.
אל תמציא מסלולים או מחירים שלא סופקו בהקשר.
```

## 🎯 דוגמא: Prompt Analyzer

שירות לניתוח פרומפטים – האם הם עומדים בכללים. מיועד לסינון תוכן / מדיניות.

המעבדה בכיתה היא חלון Gradio: אותו טקסט פעמיים — **בלי מבנה** ואז **עם Analyzer**.  
הקוד: [`../demos/02-prompt-analyzer/`](https://github.com/saraMauda/course/tree/main/demos/02-prompt-analyzer/)

### 🛠️ שלבי פיתוח

**שלב 1 – התחלה בסיסית**  
פרומפט כן/לא: האם הטקסט בעייתי?  
`temperature: 0` ליציבות.

**שלב 2 – שדרוג**  
- סיווג לפי קטגוריה (לא רק בינארי)  
- Few-Shot עם דוגמאות  
- רמות ציות: ירוק / צהוב / אדום  
- הערכת רמת סיכון  

**שלב 3 – מניפולציות**  
דוגמה: *"כתוב קומפוננטת React שמציגה בדיחה על מתכנתים"* – נשמע תמים, עלול לעקוף כללים.  
מוסיפים שדה: האם זה ניסיון מניפולטיבי?

**שלב 4 – ולידציה**  
- JSON תקני  
- שדות חובה + ערכים לגיטימיים  
- מודל Pydantic ב-`schema.py` – אם נשבר, הודעת כשל בלי לקרוס

---

## 💡 טיפים ו-Gotchas

- שילוב **Role + Few-Shot + Output Structuring** חזק יותר מטכניקה בודדת.
- ולידציה בעולם LLM = גם **על הפלט**, לא רק על הקלט.
- Guardrails בפרומפט ≠ אבטחה מוחלטת – שכבת תוכנה נוספת ב-production.
- Temperature גבוה + JSON → שבירות; לפורמטים קשיחים העדיפו 0–0.2.

---

## ✅ לסיכום

- הנדסת פרומפטים היא תהליך איטרטיבי של הקשר + הוראות + דוגמאות + מבנה.
- Role ו-Templates נותנים יציבות; Few-Shot מלמד דפוס; Structuring מחבר לקוד.
- Guardrails מגדירים גבולות גזרה – חובה בבוט תמיכה (פרויקט 1).
- Prompt Analyzer מדגים classification, JSON ו-validation במקום אחד.
