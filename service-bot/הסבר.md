# הסבר על הפרויקט – Service Bot

הפרויקט הוא צ'אטבוט RAG לשירות לקוחות. הוא לא ממציא תשובות: הוא מחפש במאגר של 36 שאלות ותשובות את השאלה הכי דומה, ונותן ל-LLM לנסח תשובה רק מתוך מה שנמצא.

יש ארבעה קבצי קוד ו-`dataset.json`, ובשני שלבים.

## מבנה הקבצים

```
config.py        ← הגדרות משותפות (כולם מייבאים אותו)
   ↑
build_index.py   ← שלב א׳ (offline): dataset.json → faq.npy
bot.py           ← שלב ב׳ (online): שאלה → שליפה → LLM → תשובה
   ↑
scores.py        ← כלי כיול, מייבא את retrieve מ-bot.py
```

## `config.py` – הגדרות

- **קבועים:** מודל ה-embeddings (`EMBED_MODEL`), מודל הצ'אט (`CHAT_MODEL`), כמה תוצאות לשלוף (`TOP_K=3`), הסף (`SCORE_THRESHOLD=0.45`), הודעת "אין מידע" (`NO_ANSWER`) ושם הקובץ (`VECTORS_FILE`).
- **`api_key()`** – קוראת את `COHERE_API_KEY` מ-`.env` (`load_dotenv` בראש הקובץ טוען אותו). אם המפתח חסר, התוכנית נעצרת עם הודעה ברורה.

## `build_index.py` – שלב א׳, מריצים פעם אחת

אין בו פונקציות. הוא סקריפט שרץ מלמעלה למטה:

1. קורא את `dataset.json` ושולף רק את השאלות.
2. שולח ל-Cohere בקבוצות של עד 90 (`input_type="search_document"`) ומקבל וקטור לכל שאלה.
3. מנרמל את הוקטורים (אורך 1) ושומר ב-`faq.npy`.

מריצים אותו שוב רק כש-`dataset.json` משתנה.

### מה זה `faq.npy`

טבלת מספרים בגודל 36×1024: כל שאלה במאגר הפכה לשורה של 1024 מספרים (embedding) שמייצגים את המשמעות שלה. שאלות דומות במשמעות מקבלות שורות דומות. הקובץ נשמר כדי שלא יהיה צורך לקרוא ל-Cohere (עולה כסף וזמן) בכל הפעלה. אחרי הנרמול, מכפלה פנימית בין שני וקטורים שווה לדמיון קוסינוס.

## `bot.py` – שלב ב׳, ההיגיון של הבוט

בזמן הטעינה (מחוץ לפונקציות) הוא יוצר לקוח Cohere, טוען את `dataset.json` ואת `faq.npy` לזיכרון. אחר כך יש חמש פונקציות, ובכל שאלה הן נקראות בשרשרת:

```
main() ──פותחת ממשק Gradio──► ui(query)
                                 │
                                 ▼
                             answer(query)  ← המנהלת
                              │        │
                 retrieve(query)       build_prompt(query, results)
                 (חיפוש)               (בניית הפרומפט)
                                       ואז co.chat → LLM
```

| פונקציה | תפקיד |
|---|---|
| **`retrieve(query, k)`** | הופכת את השאלה לוקטור (`input_type="search_query"`, הפוך מ-`search_document`) ומנרמלת. אחר כך `matrix @ q` נותן ציון דמיון לכל 36 השאלות. `argsort` בוחר את k הכי גבוהים. מחזירה רשימה של שאלה, תשובה וציון. |
| **`build_prompt(query, results)`** | מדביקה את התוצאות שנשלפו כ"הקשר" לתוך פרומפט שמורה ל-LLM: לענות רק לפי ההקשר, להחזיר `NO_ANSWER` אם אין מספיק מידע, ולהחזיר JSON במבנה קבוע. |
| **`answer(query)`** | המנהלת. קוראת ל-`retrieve`. אם הציון הכי גבוה מתחת ל-0.45, היא מחזירה "אין מידע" **בלי לקרוא ל-LLM בכלל** (Guardrail ראשון, חוסך כסף ומונע המצאות). אחרת היא בונה פרומפט, קוראת ל-`co.chat` עם `temperature=0` ופלט JSON, ומצרפת את `sources` לתוצאה. |
| **`ui(query)`** | מתאימה את התוצאה לממשק. מפרקת את ה-JSON של `answer` לארבעה פלטים: תשובה, מחוץ לתחום או לא, מקורות עם ציון, וה-JSON המלא. |
| **`main()`** | בונה את מסך Gradio (תיבת שאלה, ארבעה שדות פלט) ומפעילה אותו. רצה רק כשמריצים `python bot.py`, בגלל `if __name__ == "__main__"`. |

## `scores.py` – כלי כיול

מייבא רק את `retrieve` מ-`bot.py`. מריץ שאלות לדוגמה, כאלה שבתחום וכאלה שמחוץ לתחום, ומדפיס את הציון הכי גבוה של כל אחת, בלי LLM. לפי זה בוחרים את `SCORE_THRESHOLD`. הייבוא לא מפעיל את הממשק, בזכות אותו `__main__`.

## זרימה מלאה של שאלה

`"איבדתי את הפלאפון"` ← `ui` ← `answer` ← `retrieve` (ציון 0.664, מעל הסף) ← `build_prompt` ← LLM ← JSON עם `answer`, `out_of_scope` ו-`confidence` ← חוזר למסך.

שתי הגנות מונעות המצאות: הסף בקוד, וההוראה בפרומפט למקרה שהשליפה עברה את הסף אבל התשובה לא באמת מתאימה.

## הרצה

```powershell
.venv\Scripts\Activate.ps1
python build_index.py   # פעם אחת, או אחרי שינוי ב-dataset.json
python scores.py        # אופציונלי: כיול הסף
python bot.py           # http://127.0.0.1:7860
```
