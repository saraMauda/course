# דמו שיעור 10 – זיכרון וחיפוש חי

שיחה אמיתית של כמה הודעות ברצף, בשלושה מצבים: בלי זיכרון, עם זיכרון (Checkpointer + `thread_id`), ועם זיכרון + סיכום.
רואים את התשובה, **כמה הודעות נשמרו וכמה המודל קיבל**, מה בדיוק המודל קיבל, ומה קרה מאחורי הקלעים.

משפט עוגן:

> **זיכרון ≠ אמת. הזיכרון הוא רשימת הודעות שמגיעה למודל, והיא גדלה. צריך לנהל אותה.**

חיבור לשיעור 09: אותו `create_agent`. כאן מוסיפים `checkpointer` ו-middleware.
חיבור לשיעור 08: אותו סוכן, עכשיו עם שיחה ולא הודעה בודדת.
חיבור לשיעור 05: כאן ההקשר שמנפח הוא תוצאת הסריקה, כמו מקטעי RAG שם.

## הרצה

```bash
cd demos/10-memory-search
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

שימי מפתח ב-`.env`, ואז לחיצה כפולה על `הרצה.bat` או:

```bash
python app.py
```

בחלון: בוחרות **מצב זיכרון**, לוחצות על חמש הדוגמאות **לפי הסדר** (כל פעם **שלחי**), ורואות איך המספרים משתנים. **שיחה חדשה** פותחת `thread_id` חדש.

חשוב: מחליפות מצב, לוחצות **שיחה חדשה** ומתחילות את התסריט מההתחלה.

אם OpenAI חסום (רימון), הקוד עובר לבד להדגמה מקומית או ל-Gemini. פירוט ב-`.env.example`.

> **שימי לב:** החיפוש והסריקה הם stub (אין רשת בכיתה). בפרויקט 2 מחליפים ב-Tavily או Firecrawl (Firecrawl אם Tavily חסום). בהדגמה המקומית (mock) המודל עונה רק ממה שנמצא ברשימת ההודעות שקיבל. זה הזיכרון האמיתי. הסיכום בהדגמה מקומית מדומה, ועם מודל אמיתי המספרים ישתנו.

## מה להגיד, לפי התסריט

חמש הודעות, בכל מצב: «שלום, שמי דנה.» → «מה שמי?» → «חפשי כמה מסגרות לסוכנים קיימות היום» → «תסרקי את התוצאה הראשונה» → «מה שמי?»

1. **בלי זיכרון** – הודעה 2: «אני לא יודעת». «המודל קיבל הודעה אחת. אין שיחה.» הודעה 4: «אין לי כתובת לסרוק»: התוצאה מהחיפוש נעלמה. בשורת ההקשר תמיד 1–3 הודעות.
2. **עם זיכרון** – אותה שיחה. הודעה 2: «קוראים לך דנה». בשורת ההקשר: `thread_id`, ו**מספר ההודעות שגדל**: 2 → 4 → 8 → 12 → 14. «זיכרון הוא לא קסם. זו רשימת הודעות שנשלחת למודל בכל פעם.»
3. **אותו מצב, «שיחה חדשה»** – `thread_id` חדש, וההודעה «מה שמי?» חוזרת ל«לא יודעת». «בלי אותו thread_id אין שיחה.»
4. **הסריקה (הודעה 4)** – ב«מה נשלח» רואים `[נחתך: 400 תווים מתוך 1512]`. פתחי `tools.py`: «בלי החיתוך הדף כולו היה בהיסטוריה לכל ההמשך.» (אפשר לשנות `MAX_SCRAPE_CHARS` ל-5000 ולראות את התווים קופצים.)
5. **זיכרון + סיכום** – ההודעות הראשונות כמו בזיכרון רגיל. מהודעה 4 הסיכום פועל: בשורת ההקשר המספר **קטן**, ובראש «מה נשלח» מופיעה הודעת סיכום (בה כתוב «שמי דנה»). הודעה 5: «קוראים לך דנה» עם הרבה פחות הודעות מ-13. «הסיכום שומר את מה שחשוב, וההיסטוריה לא מתנפחת.»
6. **הסיכון** – הסיכום הוא מודל. אם הוא יאבד את השם, אין דרך חזרה. בדקי: מה קורה כש-`SUMMARY_KEEP` קטן מדי (כשהוא 1 או 2 אפילו השאלה הנוכחית עלולה להיכנס לסיכום).

## מה לא בדמו (בקול)

- **שאילתה גרועה → query rewrite**: skill או tool שמנסח מחדש לפני `web_search`. שלב 5 במעבדה, ופרויקט 2.
- **פלט מובנה** (`ResearchAnswer` ב-Pydantic: summary, sources, confidence): פרויקט 2.
- **Trim** במקום Summarize: חיתוך הודעות ישנות בלי מודל. זול יותר, ואובדן מידע מוחלט.
- **SQLite / Postgres** במקום `InMemorySaver`: בפרודקשן. כאן הזיכרון נמחק כשהתהליך נסגר.

## שאלות לדיון

- מתי Trim עדיף על Summarize? ← כשההיסטוריה ישנה באמת לא חשובה, ורוצים לחסוך קריאת מודל.
- מה עוד גורם ל-Context Rot חוץ מהשיחה? ← תוצאות כלים גדולות, מטא-דאטה של MCP, מסמכי RAG.
- למה צריך מקורות לצד מסקנות? ← כי הזיכרון והסיכום הם ניסוח של מודל, לא ראיה.
- Tavily או Firecrawl? ← לפי זמינות רשת (NetFree). בחירה פרקטית.
