# דמו שיעור 09 – LangChain: Harness, Tools ו-ReAct

אותה הודעה פעמיים: פעם מודל לבד (בלי Harness), פעם עם LangChain (`create_agent` + כלים).
רואים את התשובה, את מה שנשלח למודל (כולל רשימת הכלים), ואת מה שקרה מאחורי הקלעים.

משפט עוגן:

> **Agent = Model + Harness. את הלולאה כבר כתבנו ידנית. LangChain עוטפת אותה, ואנחנו מגדירות מודל, כלים, הוראות ובקרה.**

חיבור לשיעור 03: אותה לולאת ReAct (מודל → כלי → Observation → מודל). שם כתבנו אותה בעצמנו, כאן `create_agent`.
חיבור לשיעור 05: `search_sources` הוא RAG **ככלי אחד מתוך ארגז**, לא כל המערכת.
חיבור לשיעור 07: אותו רעיון של תיאור כלי. שם הוא נחשף משרת, כאן מ-`@tool`.
חיבור לשיעור 08: מי שולט בזרימה? כאן המודל. ה-Harness הוא מה ששומר עליו.

## הרצה

```bash
cd demos/09-langchain-harness
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

שימי מפתח ב-`.env`, ואז לחיצה כפולה על `הרצה.bat` או:

```bash
python app.py
```

בחלון: כותבות הודעה (או לוחצות על דוגמה) → בוחרות **בלי Harness** או **עם LangChain** → **שלחי**.

מתחת לתיבה יש חמש דוגמאות: שני כלים ברצף, כלי אחד, **כשל כלי**, חישוב, וכלי חיצוני.

אם OpenAI חסום (רימון), הקוד עובר לבד להדגמה מקומית או ל-Gemini. פירוט ב-`.env.example`.

> **שימי לב:** ה-API של LangChain מתעדכן מהר (הדמו נכתב מול `langchain` 1.x, עם `create_agent` ו-`@wrap_tool_call`). אם גרסה אחרת נותנת שגיאת import, בדקי ב-docs העדכניים או ב-Context7. הרעיון יציב, השמות לא.

## הקבצים להראות בכיתה (בסדר הזה)

| קובץ | מה יש בו |
|------|----------|
| `tools.py` | חמישה כלים עם `@tool`. ה-docstring הוא התיאור שהמודל קורא |
| `prompt.py` | System prompt: *מתי* כל כלי. בלי זה המודל מנחש |
| `harness.py` | `create_agent`, ובקרה: כלי שנכשל חוזר כ-Observation, ותקרת צעדים |
| `ask_the_model.py` | שני המצבים, ופענוח ההודעות ל«מה קרה» |
| `app.py` | החלון: הודעה, תשובה, מה נשלח, מה קרה |

`llm_client.py` הוא חיבור טכני (מודל OpenAI / Gemini של LangChain, או מודל מדומה). לא חובה לפתוח בכיתה.

## מה להגיד בכל מצב של ה-Radio

1. **בלי Harness** – «לקוחה 312 חויבה פעמיים». המודל מבטיח «החזר מלא מיד» בלי לראות חשבון. ב«מה נשלח»: אין כלים. «מודל בלי Harness הוא מוח בלי ידיים.»
2. **`tools.py`** – פונקציה רגילה + `@tool`. **התיאור הוא פרומפט:** הוא אומר *מתי*, לא רק *מה*. הצביעי על «לא למידע על לקוחה מסוימת» ב-`search_sources`.
3. **`prompt.py`** – «מתי כל כלי». אפשר להוריד את זה ולהראות מה קורה (עם מודל אמיתי).
4. **עם LangChain, דוגמה 1** – ב«מה קרה»: המודל ביקש `get_account`, ה-Harness הריץ, Observation, המודל ביקש `search_sources`, Observation, תשובה. «אנחנו לא כתבנו לולאה.»
5. **מדיניות ביטול** – כלי אחד בלבד. «המודל בחר *איזה* כלי, ולא קרא ל-`get_account` כי אין מספר לקוח.»
6. **הזמנה 13** – הכלי **זורק חריגה**. ב«מה קרה»: «נכשל. חזר כ-Observation», והתשובה: «לא הצלחתי לבדוק כרגע». **אין קריסה.** פתחי `harness.py` והצביעי על `tool_errors_as_observation`. «בלי זה החריגה הייתה מפילה את כל התהליך.»
7. **חישוב** – `calculator`. «המודל לא מחשב בראש.» ובלי Harness: «בערך 80».
8. **מזג אוויר** – `web_search`. זה stub. «בשיעור 10 מחליפים ב-Tavily או Firecrawl.»

## מה לא בדמו (בקול)

- **MCP כרשימת כלים**: שיעור 7 הראה איך. כאן הכלים מוגדרים ב-`@tool`. אותה רשימה, אותו מבנה.
- **זיכרון ו-`thread_id`**: שיעור 10.
- **LangGraph**: `create_agent` בנוי עליו. שיעור 11.

## שאלות לדיון

- למה התיאור של הכלי חשוב כל כך? ← זה מה שהמודל קורא כדי להחליט.
- מה קורה עם 30 כלים? ← המודל מתבלבל, כמו ב-MCP. מעט כלים, תיאורים חדים.
- מה עוד ה-Harness צריך לשמור? ← הקשר (Context Rot), הרשאות, sandbox, תקרת צעדים.
- מה הסיכון בכלי שמחזיר שגיאה למודל? ← המודל עלול להמציא תשובה. לכן הכלל «אם כלי נכשל – אמרי שלא הצלחת».
