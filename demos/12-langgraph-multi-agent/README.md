# דמו שיעור 12 – Multi-Agent ב-LangGraph

כמה מומחיות עובדות על שאלה אחת, בשלושה שלבים: סדרתי, במקביל (Fan-out / Fan-in), ועם `plan` שמחליט מי עובדת ולולאה עם כלל עצירה.
רואים את המסלול, **כמה זמן זה לקח**, כמה קריאות למודל, כמה סבבים, ומה כל node כתב ל-State.

משפט עוגן:

> **הסוכנות לא מדברות זו עם זו. הן כותבות ל-State, והגרף מחליט מי הבאה.**

חיבור לשיעור 08: Parallelization ו-Orchestrator–Workers, עכשיו בקוד. `plan` הוא ה-Orchestrator, שלוש המומחיות הן ה-Workers, `synthesize` הוא המאחד.
חיבור לשיעור 11: אותו `StateGraph`. הפעם עם Reducer על שדה שכמה nodes כותבים אליו, וקשת מותנית שמחזירה רשימה.
חיבור לשיעור 10: הלולאה מרחיבה חיפוש בכל סבב, כמו query rewrite.

## מה להגיד בכל שלב

1. **שלב 1 – סדרתי.** שאלה: «למה יש לי חיוב כפול? מספר לקוח 312». המסלול: `plan → kb → account → web → synthesize`. זמן **1.2 שניות**. בציר הזמן כל node מתחיל כשהקודם נגמר. «שלושה מקורות עצמאיים, ואנחנו מחכות לכל אחד בתורו.»
2. **שלב 2 – Fan-out / Fan-in.** אותה שאלה. המסלול: `plan → (account | kb | web) → synthesize`. זמן **0.4 שניות**. בציר הזמן כולם מתחילים ב-0.00. בקוד: שלוש קשתות קבועות מ-`plan`, ושלוש קשתות אל `synthesize`. «Fan-in: המאחד רץ רק אחרי שכולן סיימו.» כל מומחית כותבת **לשדה משלה** (`kb_notes`, `account_notes`, `web_notes`), ורק `sources` משותף, ולכן יש לו Reducer.
3. **שלב 3 – plan מחליט + לולאה.** אותה שאלה: `plan` בחר רק `kb` ו-`account` (אין טעם ב-web). **3 קריאות למודל במקום 4.** פתחי `route_plan`: «קשת מותנית שמחזירה *רשימה*, ו-LangGraph מריץ את כולן במקביל.»
4. **הלולאה.** שאלה: «מה מדיניות החזר?». סבב 1: מקור אחד, **פחות מ-`MIN_SOURCES`**, אז `route_after_synth` מחזירה ל-`plan`. סבב 2: החיפוש הורחב (`KB_TOP_K`, התאמה גמישה), ויש 2 מקורות. המסלול: `plan → kb → synthesize → plan → kb → synthesize → END`. **זה כלל העצירה:** מספיק מקורות, או נגמרו הסבבים.
5. **כשל חלקי.** שאלה: «מה החדשות האחרונות על חיוב כפול?». `web` נופל, וה-node תופס את החריגה וכותב `שגיאה: ...` לשדה שלו. הגרף ממשיך, והתשובה כוללת «התשובה חלקית». «שאלה לכיתה: מה הייתה האלטרנטיבה? לקרוס? לנסות שוב? זו החלטה של מוצר.»
6. **אין מידע בכלל.** שאלה: «מה מזג האוויר?». 0 מקורות, 3 סבבים, ואז **עצירה**. «בלי תקרה, זו לולאה אינסופית. `recursion_limit` של LangGraph הוא רשת ביטחון אחרונה, לא כלל עצירה.»
7. **Mermaid.** מעתיקות ל-mermaid.live. בשלב 3 הקשתות המותנות מנוקדות.

## Global מול Local

- **Global (ב-State):** `question`, `plan`, `attempt`, `sources`, ההערות, `draft_answer`. מה שהשלבים הבאים צריכים.
- **Local (בתוך ה-node):** התוצאה הגולמית של החיפוש. ה-node כותב ל-State רק **תמצית** (`kb_notes`). אחרת חוזרים ל-Context Rot.

## מה לא בדמו (בקול)

- **Critic** (Evaluator–Optimizer בגרף): אפשר להוסיף node אחרי `synthesize`.
- **`Send`** (Fan-out דינמי לפי מספר פריטים): רק מוזכר.
- **עצירה לאדם:** שיעור 13.
- **Rate limits:** מגבילות מקביליות ב-API אמיתי.

## שאלות לדיון

- מה קורה ל-Fan-in אם אחת המומחיות לא רצה (למשל `plan` לא בחר `web`)? ← כאן זה עובד כי כל המומחיות שנבחרו רצות באותו צעד, ו-`synthesize` רצה אחריהן.
- למה לא לתת לכל המומחיות אותו System prompt? ← זהות ברורה = פחות בלבול, ואפשר לבדוק כל אחת בנפרד.
- מתי שלב 2 עדיף על שלב 3? ← כשרוצים הכי מהר ולא אכפת מעלות. שלב 3 חוסך קריאות כשלא כל מקור נחוץ.
- איפה הסיכון בלולאה? ← `MIN_SOURCES` גבוה מדי = סבבים מיותרים. בלי `MAX_LOOPS` = לולאה ללא סוף.
