# דמו שיעור 07 – MCP

אותה בקשה פעמיים: פעם בלי MCP (ה-Host לבד), פעם עם MCP (Host + Client + Server).
רואים את התשובה, את הפרומפט שנשלח (כולל ה-Tools), ואת מה שקרה מאחורי הקלעים.

משפט עוגן:

> **אנחנו לא יודעות מראש איזה Tool ייבחר – המודל בוחר. ה-Host שואל את השרת מה יש, ומריץ.**

חיבור לשיעור 01: אותה לולאת Function Calling. ההבדל – הפונקציות **לא נמצאות** בקוד של ה-Host. הן חיות בשרת נפרד, וה-Host מגלה אותן ב-`list_tools`.
חיבור לשיעור 03: אותם `lookup_bill` ו-`lookup_policy`, רק שעברו לשרת.
חיבור לשיעור 06: Skill אומר *איך* לעבוד. MCP נותן *במה* לגעת.

## הרצה

```bash
cd demos/07-mcp
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

שימי מפתח ב-`.env`, ואז לחיצה כפולה על `הרצה.bat` או:

```bash
python app.py
```

בחלון: כותבות בקשה (או לוחצות על דוגמה) → בוחרות **בלי MCP** או **עם MCP** → **שלחי**.

אין צורך להפעיל את `server.py` ידנית. ה-Client מריץ אותו בעצמו, כתהליך נפרד, בכל בקשה.

מתחת לתיבה יש שלוש דוגמאות: חיוב כפול, חיוב תקין, ומחוץ לתחום.

אם OpenAI חסום (רימון), הקוד עובר לבד להדגמה מקומית או ל-Gemini. פירוט ב-`.env.example`.

## הקבצים להראות בכיתה (בסדר הזה)

| קובץ | תפקיד ב-MCP | מה יש בו |
|------|-------------|----------|
| `server.py` | **Server** | שני Tools עם `@mcp.tool()`. בלי מודל, בלי Host |
| `client.py` | **Client** | `connect_to_server`, `list_tools`, `call_tool`. גנרי – לא מכיר את `lookup_bill` |
| `ask_the_model.py` | **Host** | מחבר, מגלה, מצרף Tools לקריאה, ולולאה עד תשובה |
| `app.py` | | החלון: בקשה, תשובה, מה נשלח, מה קרה |

`llm_client.py` הוא חיבור טכני (OpenAI / Gemini / הדגמה מקומית). לא חובה לפתוח בכיתה.

> כל Server הוא בעצם שלוש יכולות אפשריות: **Tools**, **Resources**, **Prompts**. בדמו רק Tools. השאר מוסברים בקול.

## מה להגיד בכל מצב של ה-Radio

1. **בלי MCP** – «לקוחה 312 חויבה פעמיים». המודל מבטיח «החזר מלא מיד», בלי לראות חשבון. ב«מה נשלח»: «לא חוברו שרתי MCP. אין Tools».
2. **`server.py`** – פונקציה רגילה + `@mcp.tool()`. ה-docstring הוא התיאור שהמודל יקרא. אין כאן מודל.
3. **`client.py`** – שלוש פעולות בלבד. הוא לא יודע מה יש בשרת.
4. **עם MCP** – ב«מה קרה»: הרצת השרת → `list_tools` → המודל בוחר `lookup_bill` → ה-Client מפעיל → תוצאה → `lookup_policy` → תשובה. שני סבבים, ו**לא ידענו מראש** מה ייבחר.
5. **לקוחה 100** – אותו מסלול, תוצאה אחרת: חיוב אחד, אין החזר. הנתון מהשרת, לא מהניחוש.
6. **מזג אוויר** – אין Tool מתאים, המודל לא מפעיל כלום. ה-Host מציע, המודל מחליט.

## שאלות לדיון

- מה היה קורה אם נוסיף עוד שרת (למשל מזג אוויר)? ← Client נוסף ב-Host, ועוד Tools ברשימה.
- איזה Tool מסוכן לחשוף? ← אבטחה: הרשאות, קריאה בלבד.
- Local או Remote? כאן Local (stdio). בענן – HTTP.
